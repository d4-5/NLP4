# NER Notes — Lab 10

## 1. Обраний pipeline
Для ЛР10 обрано `Stanza` з українським pipeline `uk` і процесорами `tokenize,ner`.

Чому саме `Stanza`:
- є готова підтримка української мови;
- pipeline зручно працює з `start_char/end_char`, тому його легко порівнювати з gold-розміткою корпусу;
- для лабораторної зручно будувати практичний baseline inference без fine-tuning.

## 2. Які сутності pipeline вміє з коробки
У звіті я нормалізую model labels до схеми корпусу:
- `PER/PERSON -> PERS`
- `ORG -> ORG`
- `DATE -> DATE`
- `MONEY -> MON`
- `LOC/GPE -> LOC`

Для аналізу фокус зроблено на `PERS`, `ORG`, `DATE`, `MON`, `LOC`.

## 3. Які доменні сутності важливі для цього корпусу
Для корпусу держзакупівель і новин особливо важливі:
- назви компаній та установ: `ТОВ`, `ПАТ`, `ДП`, `ГО`, міністерства, департаменти, ради;
- персоналії у новинних і юридичних сюжетах;
- дати в новинних реченнях;
- грошові суми у форматах `грн`, `млн грн`, `тис грн`, `$...`;
- адміністративні та географічні назви.

Стандартний NER baseline покриває частину таких кейсів, але для доменних ORG і регулярних MONEY/DATE патернів coverage часто нестабільний.

## 4. Додані правила
У hybrid-шарі додано три осмислені правила:
- `money_rule`: regex для сум (`грн`, `тис`, `млн`, `$`, `USD`, `EUR`);
- `date_rule`: regex для дат у форматах `23 червня`, `2011 року`, `2014 р.`;
- `legal_form_org_rule` + acronym dictionary: правила для компаній/установ із префіксами `ТОВ`, `ПАТ`, `ДП`, `ГО`, а також для доменних абревіатур на кшталт `НАЗК`, `АМКУ`, `ОДА`.

Додатково є post-processing:
- `expand_org_boundaries` розширює baseline ORG span, якщо модель відкусила лапки або юридичний префікс назви.

## 5. Що стало краще після rules
Hybrid layer насамперед покращує:
- coverage для `MON`, бо regex добре ловить типові українські суми;
- coverage для `DATE`, особливо для коротких новинних патернів на кшталт `12 вересня` або `2011 року`;
- precision/coverage для `ORG`, коли базова модель знаходить тільки частину назви або пропускає абревіатури/юридичні форми.

## 6. Які помилки залишилися
Після hybrid-шару все ще лишаються:
- boundary errors у довгих назвах установ;
- type errors між `ORG` і `LOC` або між `ORG` і суміжними назвами;
- пропуски складних доменних сутностей без явного регулярного патерну;
- неоднозначні випадки з лапками, вкладеними назвами та дуже довгими спанами.

## 7. Що я б фіксив далі
Наступні кроки для покращення:
- розширити словники державних органів, банків, рад, університетів і типових абревіатур;
- додати спеціальне conflict resolution для nested ORG spans;
- окремо порівняти `Stanza` зі `spaCy`, щоб побачити, який baseline дає кращі PERSON/ORG boundary на цьому корпусі.
