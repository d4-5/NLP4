## 1. Пам'ять стану (Короткострокова)
Об'єкт `FlowState` слугує короткостроковою пам'яттю для одного виконання потоку NLP.

### Що зберігається:
- `case_id`: Унікальний ідентифікатор транзакції.
- `raw_input`: Оригінальний текст, наданий користувачем.
- `clean_text`: Очищена версія вхідних даних.
- `route`: Вибраний шлях пайплайну (наприклад, finance_extraction).
- `extraction_parsed`: JSON-вихід етапу виконання.
- `validation_issues`: Список помилок, знайдених валідатором або рецензентом.
- `fallback_output`: Результат механізму fallback, якщо він був активований.
- `status`: Поточний етап та індикатор успіху/відмови.
- `steps`: Аудиторський слід усіх переходів.

### Що НЕ зберігається:
- **API ключі / Облікові дані**: Ніколи не зберігаються у стані або логах.
- **Великі бінарні об'єкти**: Обробляються лише текстові дані.
- **PII (Персональні дані)**: Якщо це не потрібно для екстракції, їх слід мінімізувати або маскувати.
- **Чернетки з галюцинаціями**: Тільки фінальні або валідовані результати вважаються "істиною" для наступних кроків.

## 2. Політика знань
Ресурси знань — це зовнішні, незмінні довідкові дані, що використовуються для керування потоком.

### Ресурси знань:
- **JSON-схеми**: Знаходяться у `src/json_schema.py`. Використовуються для валідації та керування екстракцією LLM.
- **Regex-патерни**: Використовуються у `src/ie_rules.py` для fallback на основі правил.
- **Правила маршрутизації**: Визначені у системному промпті агента `TriagerAgent`.

### Правила використання:
- Файли знань доступні лише для **читання**. Потік не може змінювати схеми або правила під час виконання.
- Якщо було б впроваджено реєстр схем, він був би єдиним джерелом істини для валідації.
- Помилки пошуку знань (наприклад, невідомий маршрут) мають призводити до статусу `manual_review`.
