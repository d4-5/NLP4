# Короткий підсумок ЛР8

1. Розмір корпусу після фільтрації: `9930` документів із `11161` початкових (`min_tokens=5`, `min_chars=20`).
2. Протестовані моделі: `LSA = TfidfVectorizer + TruncatedSVD`, `LDA = CountVectorizer + LatentDirichletAllocation`.
3. Перевірені значення `k`: `5` і `8` для обох моделей.
4. Найкращі теми:
   - `LSA, k=8, topic 2` - суми контрактів і назви компаній (`грн, тов, млн, тис, вартість`).
   - `LSA, k=8, topic 5` - судові рішення та постанови (`суду, рішення, господарського, постанова`).
   - `LSA, k=8, topic 6` - переліки фірм і корпоративні зв'язки (`тов, фірми, компанія, належить`).
5. Найгірші теми:
   - `LSA, k=5, topic 3` - занадто загальна тема навколо слова `є`.
   - `LSA, k=5, topic 4` - дубль попередньої шумної теми з корпоративним шумом.
   - `LDA, k=8, topic 0` - числа, гроші та новинний шум, де в одну тему потрапили бізнес, суд і прогноз погоди.
6. Що зіпсувало слабкі теми: короткі документи, дуже загальні слова, шаблонні фрази новин і закупівель, числовий шум та змішаний корпус із різних жанрів.
7. Краща модель для цього кейсу: `LSA`, бо вона дала стабільніші й легші для ручної перевірки теми у бізнесово-юридичній частині корпусу.
8. Що варто робити далі: посилити stop-word filtering, прибрати шаблонні фрази типу `Про це повідомляється...`, перевірити `lemma_text`, спробувати `ngram_range=(1,2)` і, за потреби, моделювати окремі підкорпуси.
