## 1. Юзкейс
**Support Assistant (Помічник підтримки)**: Одноагентна система, яка класифікує вхідні тікети підтримки, витягує релевантні сутності (ID замовлень, суми, дати) та перевіряє, чи достатньо наданої інформації для ідентифікованої категорії звернення.

## 2. Реалізовані інструменти
- `classify_issue(text: str)`: Класифікує тікети на категорії: Оплата (Payment), Технічні (Technical) або Загальні (General).
- `extract_support_entities(text: str)`: Перевикористовує існуючу логіку на основі правил для витягу структурованих даних.
- `validate_support_fields(category: str, entities: dict)`: Перевіряє наявність обов'язкових полів залежно від категорії проблеми.

## 3. Метрики оцінювання
- **Загальна кількість тест-кейсів**: 10
- **Успішність викликів інструментів (Success Rate)**: 77.7% (спочатку виникали проблеми через помилки парсингу та галюцинації "Observation" з боку LLM).
- **Середня кількість викликів на задачу**: 11.2 (агент часто повторює виклики або має труднощі з багатокроковими міркуваннями).
- **Задачі з корисним використанням інструментів**: 5 / 10
- **Зайві виклики інструментів**: Спостерігалися у випадках case_003 та case_009, де агент намагався витягти сутності з дуже короткого або просто ввічливого тексту.

## 4. Ключові приклади
### Успішне використання інструментів (case_001)
- **Вхідні дані**: "Я оплатив замовлення №12345 на суму 500 грн 20.05.2026..."
- **Поведінка**: Агент викликав `classify_issue`, потім `extract_support_entities`, а потім `validate_support_fields`. Він правильно визначив, що вся інформація присутня, і надав підтвердження.

### Проблемний випадок (case_010)
- **Вхідні дані**: "Я випадково відправив 1000 доларів замість 1000 гривень. Що робити?"
- **Проблема**: Агент мав труднощі з неоднозначністю помилки валюти та галюцинував "Observation" до того, як система могла його надати. Було додано логіку обрізки (truncation) для пом'якшення цієї проблеми.

## 5. Майбутні покращення
- Впровадження кращого управління станом (state management) для запобігання нескінченним циклам або надлишковим викликам інструментів.
- Використання просунутішої LLM (наприклад, Llama-3-70b) для кращого дотримання формату ReAct.
- Додавання спеціалізованих інструментів для конкретних робочих процесів підтримки (наприклад, `check_user_status`).
